04 · Term Project

AI Study Assistant

CIS 641 System Analysis and Design, Fall 2026 · Sole analyst, designer, and developer

The problem. Students spread their school work across many tools: the learning system for due dates, a calendar for study time, a cloud folder for slides, and usually nothing at all for how much they have studied. Because these tools don't share information, a student can see that an exam is coming but not that they have barely studied for that course, and they often notice only a day or two before the exam.

What I'm building. A web application that puts courses, assignments, exams, deadlines, study schedules, and course materials in one place, tracks study hours against a weekly goal per course, and reminds the student about anything due within two days. Its AI feature compares each upcoming deadline with the time already studied and planned, then recommends up to three courses to focus on, each with a reason and a plan of study sessions the student can accept or dismiss.

The design decision I'm proudest of. The recommender is a hybrid. Fixed rules calculate the study gap (hours needed minus hours studied and planned), rank it by deadline, priority, and task type, and build the session plan. A pretrained language model only writes the explanation the student reads. The model never sets the numbers, so an invented hour or date can't reach the schedule, and if the model is slow or down, rule-based text takes over.

What I delivered this semester.

  1. 01Project proposal: problem statement, five measurable objectives, scope, stakeholders, and a feasibility study
  2. 0212 functional and 7 non-functional requirements, organized by feature into a Software Requirements Specification
  3. 03System models: UML class diagram, CRC cards, a sequence diagram, and a state machine diagram
  4. 04Architecture on the MERN stack (MongoDB, Express, React, Node.js) with Docker, so the whole system starts with one command
  5. 05A working prototype of the main screens and the recommendation rules

Next. Connect the prototype to the Express and MongoDB back end, add student accounts, plug in a local Llama 3.2 model through Ollama at no cost, and test each objective, for example that a student with an exam in 3 days and 0 hours studied gets that course recommended first.
